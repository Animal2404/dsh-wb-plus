# dsh-wb-plus 开发历程

> 主题：WorkBuddy 的社区增强版 DSH 接入插件 `dsh-wb-plus`
>
> 覆盖范围：从最初的侧边栏入口、面板重构、号池与用量功能，到 1.2.1 的跨区域共享号池修复。
>
> 仓库：https://github.com/Animal2404/dsh-wb-plus
>
> 当前版本：`1.2.1`（提交 `4ebb547`）

---

## 一、项目目标

把本机 WorkBuddy 桌面端的登录状态接入 DeepSeek Harness，并提供一个完整的可视化管理面板。

核心目标：

1. 国内版、国际版同时可用，互不干扰。
2. 号池统一展示两边账号，支持选择、签到、积分、限流状态。
3. 模型能力完整展示：倍率、档位、最大上下文、最大输出、图片能力。
4. 用量可追踪：调用次数、首 token、token 速度、token 总量、缓存命中、token / 积分。
5. 界面稳定：不压输入框、不随窗口变宽失控、刷新不闪空、设置可记忆。
6. 修复必须可验证：离线测试 + 真实浏览器渲染 + 真实页面交互 + 可复现补丁。

## 二、整体开发历程

### 阶段 1：从设置卡片变成独立面板

**目标**

原本 WorkBuddy 只是设置页里的一张配置卡片。需要把它做成侧边栏入口，后续再接入主区域标签页。

**主要工作**

- 注册侧边栏槽位，增加可展开面板。
- 兼容两种模型推理结构：`supportedEfforts/defaultEffort` 与 `efforts: [{ id }]`。
- 增加 React error boundary，避免单个数据异常导致整条入口消失。
- 收缩态只显示总积分，不显示“签到积分 / 总积分”两项。
- 国际版不显示签到按钮，签到只对国内版开放。
- 模型倍率缺失时不渲染 `x0` 或 `NaN`。
- 上下文档位按原生窗口判断：不超过 200K 时只显示禁用档位，否则显示 `200K` 与原生档位。

**遇到的问题**

- 槽位注册报错：`list slot "sidebar.footer.action" requires options.id`。
- 注册后整条入口消失，报 `Cannot read properties of undefined (reading 'map')`。

**修复方式**

- 槽位注册补上 `id`。
- 新增统一的推理档位解析函数，并对所有数组访问增加类型守卫。
- 用错误边界包住展开态和收缩态，单点异常不再带下线整个入口。

### 阶段 2：视觉系统重做

**背景**

第一轮“优化 UI”只调整了间距、行高、圆角，用户明确表示“还是同一个风格”。这说明方向本身不对。

**真正的问题**

- 没有入场动效。
- 只有 `:active { opacity }`，没有按压缩放反馈。
- 触屏设备会出现假 hover。
- 没有 `prefers-reduced-motion`。
- 使用硬边框、浏览器默认复选框和单选按钮。
- 主按钮是近白色大色块，视觉粗糙。

**修复方式**

- 面板从 `transform-origin: center` 改为 `bottom left`。
- 增加 `@starting-style`：`scale(.96) + translateY(8px) + opacity:0`，220ms 强 ease-out。
- 按压反馈由透明度改为 `scale(.97)`，160ms。
- hover 全部限制在 `@media (hover: hover) and (pointer: fine)`。
- 支持 `prefers-reduced-motion`，保留透明度变化、移除位移动画。
- 硬边框改为半透明发丝线 + 三层阴影。
- 自绘复选框、开关、档位药丸。
- 积分数字使用 `tabular-nums`，避免跳动。
- 滚动区底部增加渐变溶解，避免内容被硬切。

**测量陷阱**

几何自检一度报告 `overlaps: 10`，看起来像布局错误。实际是滚动区外已被裁剪的行，`getBoundingClientRect()` 仍返回布局位置。改用与滚动容器求交后的可见矩形重新测量，结果是 `overlapsOnScreen: 0`。这不是布局问题，没有修改本来正确的代码。

### 阶段 3：模型列表与积分展示

**主要工作**

- 已勾选模型顶置，使用稳定分区排序：`filter(已勾选).concat(filter(未勾选))`。
- 积分显示守卫从 `typeof value === "number"` 改为 `Number.isFinite`，因为 `typeof NaN === "number"` 会漏过。
- 取不到积分时显示灰色破折号，不再显示 `NaN`。
- 账号积分由紧凑写法改为完整千分位，例如 `2,098`。

**遇到的问题**

- 已勾选模型重复渲染时会重新排序。
- `NaN` 会通过 `typeof` 判断，直接渲染到界面。
- 积分显示“不完整”并不是 CSS 裁切，而是格式化函数把 `2098` 压成了 `2.1K`。

**修复方式**

- 排序改为稳定分区，段内顺序保持 provider 返回顺序。
- 所有数值判断改为 `Number.isFinite`。
- 新增完整数字格式化函数，账号积分显示千分位，并移除潜在裁切宽度限制。

### 阶段 4：号池与 Token 用量

**主要工作**

- 宿主订阅会话事件，按 `data.message.source.provider` 过滤，只统计 `workbuddy` 与 `workbuddy-global`。
- 新增 `/plugins/dsh-connect-workbuddy/tokens` 路由。
- 号池沿用宿主已有的区域参数与 `settings.accounts[region]` 选择机制，不新造存储。
- 每条账号独立获取积分，单个账号失败只降级它自己那一行。

**关键发现**

DSH 会话记录不持久化 usage，usage 只作为实时事件存在。因此需要宿主主动订阅并记账。

**遇到的问题**

- 如果账号行共用一次请求，单个账号失败会把整个列表打空。
- Token 口径容易混入其他 provider。

**修复方式**

- 使用 `Promise.allSettled`，逐账号降级。
- 增加 `scope` 与 `ignoredProviders`，明确只统计两个 WorkBuddy provider。

### 阶段 5：添加账号流程返工

**最初错误做法**

设计成让用户粘贴一段 JSON。

**用户明确否决**

用户不需要看到、准备或理解 JSON。

**重新认识**

插件账号本来就来自 WorkBuddy 桌面端登录凭据文件。用户登录桌面端后，插件重扫即可发现账号。插件自有 JSON 存储是多余的并行存储。

**修复方式**

- 删除插件自有号池存储、校验器和相关路由。
- 改为登录引导流程：
  1. 打开登录链接。
  2. 用户完成登录。
  3. 点击“我已完成登录，收进号池”。
  4. 调用现有账号刷新接口重扫。
  5. 比对前后数量。
  6. 有新增则刷新；没有新增则明确提示，不静默成功。

### 阶段 6：主区域标签页与卡片布局

**目标**

取消侧边栏入口，把 WorkBuddy 做成主区域第三个标签页。

**遇到的问题**

1. 标签页里没有卡片样式，复选框、开关、药丸都像裸控件。
2. 模型列表没有高度限制，直接压到输入框上。
3. 面板被压缩后内容溢出，无法滚动。
4. 标签页切换回来后出现“未登录 / 0 个账号”闪空。

**根因**

- 视觉变量只声明在侧边栏根节点 `.dsm-wb-side-layer`，而标签页根节点是兄弟节点 `.dsm-wb-view-root`，无法继承。
- 模型列表被解除 `max-height`。
- 面板使用 `flex: 1 1 auto`，内容超高时被压缩，但 `overflow: visible` 让内容溢出。
- 标签页卸载后重新挂载，所有 `useState` 从空开始。

**修复方式**

- 视觉变量同时声明在两个根节点。
- 标签页内恢复模型列表与号池列表高度上限。
- 标签页底部增加动态留白，由运行时测量输入框高度决定。
- 面板改为 `flex: 0 0 auto`，由根容器负责滚动。
- 新增模块级缓存，重新挂载时先绘制上次数据，再后台刷新。

---

### 阶段 7：用量分析与持久化

**主要工作**

- 新增“账号池 / 用量”切换。
- 用量包含头条数字、按小时堆叠图、按账号 / 模型 / 域三张明细表。
- 支持 1 天、3 天、7 天、14 天、全部。
- 新增 `token / 积分`、已耗积分、缓存命中。
- 时序图增加 Y 轴刻度、网格线和 X 轴时刻。
- 明细表补缓存命中列。
- 用量账本落盘，重启不丢。
- 号池读条从账本按账号重建，重启不归零。

**遇到的问题**

- 缓存命中一开始显示百分比，用户要求改成 token 数。
- 失败尝试位置不合理，用户要求放到最后。
- 图表在密集窗口横向溢出。
- 零 token 桶会画出假柱。
- 客户端断线被错误计为账号失败。

**修复方式**

- 缓存命中改为 token 数，三张明细表同步。
- 失败尝试移到最末。
- 密集窗口使用更窄柱宽和更小间距。
- 零 token 桶高度强制为 0。
- 客户端断线不计入上游失败。

### 阶段 8：偏好保存与切换提速

**用户反馈**

- 切到国际版后，重新进入又变回国内版。
- 国内 / 国际切换加载很久。

**修复方式**

- 将区域、标签页、用量窗口写入 `localStorage["dsh.workbuddy.panel.prefs"]`。
- 新增 `/usage?fast=1`，只返回本地数据，不触发上游请求。
- 修复切换时请求打错供应商的问题。
- 移除一次重复的积分请求。
- 读凭证从 `resolve()` 改为 `current()`，避免快速路径触发 token 刷新。

**效果**

- 快速路径从约 1614ms 降到约 60ms。
- 首次冷路径约 445ms，热路径约 40–142ms。

### 阶段 9：冷却与模型限流

**用户反馈**

- 账号被 429 限流后，界面仍显示可用。
- 需要区分账号完全冷却与单模型限流。
- 单模型限流时显示“限流恢复时间”。

**根因**

- 聊天被拒时的回调收到了整个结果对象，导致错误匹配失败。
- 一次成功的积分读取会清掉刚记录的冷却状态。
- 上游 `code 6004` 实际是模型级限流，不是账号完全冷却。

**修复方式**

- 冷却表由聊天 shim 与状态路由共享。
- 修复回调参数传递。
- 积分读取成功不再清除冷却。
- 健康状态拆成两张表：
  - `poolHealth`：账号级冷却。
  - `poolModelHealth`：模型级限流，键为 `accountId + NUL + modelId`。
- 账号完全冷却显示“冷却中 · 冷却至 …”。
- 仅模型限流显示“模型限流”。
- 模型行显示“限流恢复时间 HH:mm / MM/DD HH:mm”。

## 三、1.2.0：跨区域共享号池

### 需求

用户要求：

- 号池直接显示国内与国际总数，不区分开。
- 区分开的只是模型选择。
- 每个账号行带区域标识。
- 账号切换、单账号签到、令牌到期按该行所属区域执行。

### 实现

- 号池改为跨区域共享。
- 同时请求 `/pool/credits?region=cn` 与 `region=global`。
- 使用复合键 `region + NUL + accountId` 合并。
- 账号行新增 `CN` / `AI` 标识。
- 汇总数字为两边之和。
- 国内 / 国际切换只改变模型列表。
- 一键签到只针对国内账号。

### 遇到的问题

1. 共享号池后，点击账号没有可见选中状态。
2. 切换国内 / 国际时，左侧积分跟着变化。
3. 号池合并后出现两个“当前账号”，因为国内和国际各有一个。
4. 切换模型区域后，左侧账号名会被当前模型区域的账号覆盖。

## 四、1.2.1：修复共享号池选择与积分联动

### 问题 1：点击账号没有选中效果

**现象**

号池能显示所有账号，但点击账号没有高亮，也没有明显反馈。

**根因**

宿主 `/pool/credits` 返回的账号行没有 `selected` 字段。客户端合并后，`account.selected === true` 永远为假。

**修复**

宿主在 `/pool/credits` 中读取当前区域 store 的选中账号，并为每个账号补上 `selected` 标记：

```js
const selectedAccountId = (await store.accounts()).find((account) => account.selected)?.id;
const accounts = settled.map((account) => ({
  ...account,
  selected: account.id === selectedAccountId
}));
```

**验证**

- 宿主路由测试断言响应中恰好一个账号 `selected === true`。
- 渲染测试模拟点击账号，断言：
  - 点击后恰好一个账号高亮。
  - 点击的账号就是高亮账号。
  - 对应按钮 `aria-pressed=true`。

---

### 问题 2：切换国内 / 国际影响左侧积分

**现象**

切换模型区域时，左侧积分卡跟着变成另一个区域的账号积分。

**根因**

积分卡仍读取当前模型区域的 `status.credits` 与 `status.checkin`。

**修复**

积分卡改为跟随共享号池中选中的账号：

```js
const focusedPoolAccount =
  accounts.find((account) => account.id === focusedAccountKey)
  ?? accounts.find((account) => account.selected === true)
  ?? accounts[0];
```

随后使用：

- `poolCredits[focusedPoolAccount.id]`
- `poolCheckin[focusedPoolAccount.id]`
- `poolDetails[focusedPoolAccount.id]`

模型区域切换只改变模型列表，不再影响左侧积分。

---

### 问题 3：共享号池出现两个高亮账号

**现象**

国内、国际各自有一个运行账号，合并后两个账号都显示为当前。

**修复**

- 保留每个区域自己的运行账号。
- 共享卡片只维护一个视觉焦点 `focusedAccountKey`。
- 点击账号时：
  1. 更新该区域运行账号。
  2. 更新视觉焦点。
  3. 写入本地偏好。
  4. 立即刷新号池数据。

---

### 问题 4：切换模型区域后左侧账号名被覆盖

**现象**

切换模型区域后，左侧积分数值不变，但账号名变回该模型区域的账号。

**根因**

旧的账号名回退逻辑仍会读取当前模型区域的 `status.accountName`。

**修复**

- 左侧账号名只使用号池焦点账号。
- 模型区域切换后重新读取本地保存的焦点账号。

```js
useEffect(() => {
  const saved = readPanelPreferences().focusedAccount;
  if (typeof saved === "string" && saved !== "") {
    setFocusedAccountKey(saved);
  }
}, [region]);
```

## 七、关键经验

1. **先确认真实根因，再改界面。**
   积分显示不完整不是 CSS 裁切，而是数字被格式化压缩。

2. **共享视图必须只有一个视觉主语。**
   国内、国际可以各自保留运行账号，但合并卡片只能有一个当前焦点。

3. **模型区域与号池区域是两个概念。**
   模型区域只决定模型列表，不能影响号池账号与积分。

4. **测试要覆盖交互，不只覆盖文本。**
   本次新增点击账号、区域切换、积分稳定性断言。

5. **补丁必须从干净上游验证。**
   只在已打补丁的目录里套补丁会产生假冲突。

6. **真实页面验证不可省略。**
   离线测试通过不代表实际交互正确，本次就是通过真实页面发现账号名仍被模型区域覆盖。
